# 命名沿革与历史版本

> 本文记录本项目从最初形态到现名的完整演进，并留档各阶段的**源码与二进制**。

---

## 一、名称演进一览

```
qqcheck  ──→  qqq  ──→  ZakoQLook (zql)
  │            │            │
  │            │            └─ 现名（2026-10-05 定名，本仓库）
  │            └─ 过渡名（2026-10-04，重构期）
  └─ 最初名（2026-09-11，QQ 本地数据只读查询工具）
```

| 时期 | 名称 | 定位 | 判据 |
|---|---|---|---|
| 2026-09-11 起 | **qqcheck** | QQ 本地数据只读查询 | 痕迹评分 |
| 2026-10-04 | **qqcheck v2.1 / v2.2** | 同上 + 机器接口 | 痕迹评分 |
| 2026-10-04 | **qqq** | 重构为本地解密查询 | **权威表** |
| 2026-10-05 | **ZakoQLook (zql)** | 现行版本 | 权威表 |

## 二、各阶段说明

### 阶段一 · qqcheck（2026-09-11 起）

```
定位   QQ 本地数据只读查询工具（仅限本人设备/账号，全程离线）
实现   Python 版（qqcheck.py）→ 重写为 Go 版（v2.0）
形态   qqcheck_arm64 / qqcheck_armv7（完整版）
       qqcheck_lite_arm64（轻量版，无 SQL 依赖）
判据   痕迹评分：
         · 群文件记录表 TroopFileTansferItemEntity<群号>
         · 群头衔缓存 "<群号>-u_<uid>"
       + 号码→UID 映射、聊天列表等辅助证据

已知局限（后来才定位）
   退群后上述痕迹【不清除】→ 会被判为"仍在群"（误判）
   实测本机 103 个有痕迹的群中，18 个已不在权威表（约 17% 误判面）
```

**留档**：`v2.0_qqcheck/`（源码 + 二进制）

---

### 阶段二 · qqcheck v2.1 / v2.2（2026-10-04）

```
v2.1 新增   机器友好接口
              · JSON 顶层字段 in_group / best_score / confidence
              · --in-group（只输出 true/false）
              · --strict-exit（退出码 0=在群 / 1=不在群）
              · 未知子命令改为返回非 0

v2.2 新增   号码类型区分（频道 / 群 / QQ号）
              依据位数区间（群号 5~12 位 / 频道 16~18 位）+ 数据域痕迹

本阶段仍用痕迹判据，未解决根本的误判问题
```

**留档**：`v2.1-2.2_qqcheck/`（源码 + 二进制 + CHANGELOG）

---

### 阶段三 · qqq（2026-10-04）

```
重构要点
  · 从"读明文痕迹"升级为"解密 NTQQ 数据库"
  · 判据改为 QQ 自身的权威表 group_info.db / group_list
  · Go 单文件实现（含 SQLCipher 解密核）

首次解决误判：已退群 → 判 false，与 QQ 内实际一致
```

---

### 阶段四 · ZakoQLook (zql)（2026-10-05 定名）

```
命名由来
  Zako（杂鱼，项目线）+ Q（QQ）+ Look（查看）
  —— 由项目所有者裁定

版本   v1.0 → v1.1（17 个命令）
特性   · 零依赖单文件二进制（arm64）
       · 退出码语义化，调用方无需解析文本
       · 解密结果带缓存
       · 消息检索强制限定在本人已加入的群

本仓库即其官方源。
```

## 五、为什么改名

```
① qqcheck → qqq
   原设计侧重"验证"（真假判断），且名字所指范围窄；
   重构后能力扩展到"查询"（资料/群/成员/等级/消息），需要新名。

② qqq → ZakoQLook (zql)
   qqq 过于泛化、与系统命令无区分度；
   定名为 ZakoQLook，取"杂鱼 + QQ + 查看"三段，
   命令名简化为 zql（3 字符，便于 shell 高频调用）。
```
