# 原理与实现

---

## 一、为什么不用"痕迹猜测"

旧版群验证依赖痕迹：

```
TroopFileTansferItemEntity<群号>   群文件记录表
"<群号>-u_<uid>"                   群成员头衔缓存
```

问题：**退群后这些痕迹不清除**，导致永久误判。

实测对比（本机）：

| 群号 | 真实状态 | 痕迹判据 | 权威判据 |
|---|---|---|---|
| 123456789 | 在群 | true ✓ | true ✓ |
| 123456795 | 在群 | true ✓ | true ✓ |
| 234567890 | 已退群 | **true ✗** | false ✓ |
| 345678901 | 已退群 | **true ✗** | false ✓ |

本机 103 个有痕迹的群中，18 个不在权威表中（约 17% 误判面）。

**结论**：改用 QQ 自身的权威表 `group_info.db / group_list`。

## 二、数据获取链路（纯离线）

```
① uid 与本人 QQ 号
   <pkg>/files/uid/<QQ号>###<uid>       ← QQ 自存的明文文件名
   优点：不需解密、不需内存读取、不需 login.db

② 解密参数
   rand ← 库头 1024 字节内 'QQ_NT DB' 后 protobuf field 2（8 个可打印字符）
   passphrase = md5( md5(uid) + rand )
   enc_key    = PBKDF2-HMAC-SHA512(passphrase, salt, 4000, 32)

③ 页结构
   page 4096 / crypto_reserve 48
   第 1 页: [salt(16)][CT(4032)][IV(16)][HMAC(20)][pad(12)]
   第 N 页: [CT(4048)][IV(16)][HMAC(20)][pad(12)]
   解密: AES-256-CBC；校验: HMAC-SHA1（2^-160 判据）

④ 解密实现为【流式】
   逐页 ReadAt → 解密 → Write，缓冲复用
   峰值内存 ≈ 13KB（与库大小无关，632MB 库亦如此）
```

**不依赖**：root 内存 dump、Frida、login.db、联网、协议端登录。

## 四、性能

```
解密：profile_info.db 21MB 约 1s
      group_info.db   21MB 约 1s
      nt_msg.db      632MB 约 6.7s

缓存命中（校验 size+mtime 后复用）：
      group-count 55ms / in-group 63ms / self-qq 46ms

内存：流式处理，峰值约 13KB
```

## 五、已知边界

```
可读：本地已缓存的一切（本人资料/好友/群/成员/消息/等级头衔）
不可读：
  · 服务端实时数据（在线状态、正在输入）
  · 未同步过的历史（本地无缓存）
  · 服务端不下发的字段（他人手机号、实名）
  · QQ 频道"已加入"判定 —— 缺权威表（见下）

频道问题详述：
  对外频道号是【字符串】（如 sample-channel / YHycZ07000604Z / pd07843201）
  库内是【16-18 位内部 ID】
  两者映射位置未定位；候选来源 `_GPro_UserLevel__user_level_<ID>`(26 个) /
  `_GPro__feed_new_`(45) / `direct_node_list.42052`(16) / 并集(55)
  → 需以实际加入数标定后方可实现
```

## 六、与其它方案的区别

| 方案 | 是否登录 | 风控风险 | 数据范围 | 本工具 |
|---|---|---|---|---|
| 协议端（NapCat/OneBot 等）| 是 | 有 | 完整（含实时）| ✗ 不采用 |
| 内存 dump / Frida | 否 | 无 | 完整 | ✗ 不采用 |
| **本地库离线解密** | **否** | **无** | **本地缓存** | **✓ 本工具** |

选择理由：无账号风控风险、无需注入、可离线复现。
代价：只能读本地已缓存的数据。

## 七、合规边界

```
· 仅限本人设备、本人账号、本地操作
· 全链路离线（不联网；唯一网络行为在开发期抓取公开资料）
· 只读副本，不修改 QQ 数据、不注入
· 不传播数据；测试完毕应清理明文缓存
· 与开源同类项目定位一致（qq-group-digest / ntqq-db-toolkit 等）
```
