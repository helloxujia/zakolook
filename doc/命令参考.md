## 二、本人信息

### `accounts`

列出账号 —— `空间 / QQ号 / 昵称 / 活动-历史`（制表符分隔）。

```bash
$ZQL accounts
# 主空间      100000001  示例昵称A  活动
# 分身(u998)  100000002  示例昵称B  活动
# 主空间      100000003  示例昵称C  历史
```

**活动** = 该账号库文件最近写入者，即**当前在线账户**；
**历史** = 同一账号空间登录过其他 QQ 时保留的旧库目录（早已不用）。

> 一个空间只有 1 个账号时通常只出现 1 行。带 `--json` 输出
> `{"accounts":[{"space","qq","name","active"}...]}`。

**为何需要它**：同一账号空间可能并存多个库目录（该空间登录过多个 QQ）。
先用它确认"哪个是在线账户"，再用 `--qq` 定向查询该账号 —— 两者配合即可
在**应用分身 / 多账号**场景下精确取数。


### `self`
本人完整资料。

```
用法：zql self [--json] [--space all|main|dual]
输出：QQ号 / 昵称 / 签名 / 性别 / UID
实测：
  QQ号: 100000001
  昵称: 示例昵称
  签名: 泥是在找我嘛，嘿嘿，本鱼可不是这么好糊弄的( ´ ▽ ` )ノ
  性别: 女
  UID:  u_EXAMPLE0000000000000000
```

### `self-qq` / `self-name` / `self-sign`

> 均可加 `--qq <QQ号>` 指定账号；不加则取**当前活动账号**（见 `accounts`）。
仅输出单个值（便于捕获）。

```
实测：
  zql self-qq     → 100000001
  zql self-name   → 示例昵称
  zql self-sign   → 泥是在找我嘛，…
```

### `self-level`
本人 QQ 等级。

```
用法：zql self-level
输出：数字
实测：16
```

## 八、消息检索（范围受限）

### `msgs <群号> [--kw 词] [--n N] [--days D]`
在**指定群**范围内检索消息。

```
用法：zql msgs <群号> [--kw 关键词] [--n 条数] [--days 天数] [--json]

  # 关键词检索

  # 越界保护
  zql msgs 234567890 --n 2
  → 该群不在已加入列表，检索已限定在本人所在群范围

  # 最近消息
  zql msgs 123456789 --n 5
  → 10-04 16:09		system	[100000006] | […] | 示例昵称T | 加入了群聊。

消息类型（kind）：text / image / file / audio / video / sticker /
                  reply / forward / system / mixed / other
```

## 九、通用选项

| 选项 | 适用 | 说明 |
|---|---|---|
| `--json` | 全部 | 结构化输出 |
| `--space all\|main\|dual` | 全部 | 限定账号空间（默认 all） |
| `--qq <QQ号>` | 全部 | 限定账号（同一空间登录过多个 QQ 时用，见 `accounts`） |
| `--fresh` | 全部 | 强制重新解密 |
| `--quiet` | 全部 | 抑制 `#` 提示 |
| `--all` | 全部 | 多空间时都输出 |
| `--count` | groups | 仅输出数量 |
| `--n N` | group-members / msgs | 限制条数 |
| `--kw 词` | msgs | 关键词 |
| `--days D` | msgs | 时间范围（天） |
| `--role R` | self-groups | 角色筛选（群主/管理员/成员） |

## 十、字段勘误（v1.2 ~ v1.5）

### `profile_info_v6."24103"` = **年龄**，不是 QQ 等级（v1.4）

旧实现（v1.0~v1.3）用该字段充当「QQ 等级」，**错误**。

**验证：出生年 + 24103 ≈ 当年年份（14/14 吻合）**

| QQ | `24103` | 出生年 | 2026 − 出生年 |
|---|---|---|---|
| 100000001（我） | 16 | 2009 | 17 ✓ |
| 100000007 | 37 | 1989 | 37 ✓ |
| 100000008 | 19 | 2007 | 19 ✓ |
| 100000009 | 29 | 1996 | 30 ✓ |
| 100000010 | 92 | 1934 | 92 ✓ |
| 100000011 | 4 | 2022 | 4 ✓ |

→ 现按实际语义改名：

```
zql self-age            本人年龄（本地资料 24103）
zql user-age <QQ号>     指定 QQ 的年龄
zql self-level          （已废弃）本地库不含 QQ 账号等级
zql user-level <QQ号>   （已废弃）同上
```

### QQ 账号等级（客户端显示的 `Lv.NN`）本地不可得（v1.4）

```
QQ 账号等级为**服务端数据**，本地数据库不含。

已排查：profile_info.db / group_info.db / nt_msg.db 全表扫描
        + QQ 目录下 mmkv / shared_prefs / *.json
        → 均未找到客户端显示的等级值

→ 本工具为纯离线，无法提供该项；请以 QQ 客户端为准。

（注意区分：本工具的 group-level 查的是**群等级**，那是本地有的，见下）
```

### 群等级字段：`group_member3."64035"`（v1.3 起）

```
QQ 客户端显示「LV54」→ 数据库 64035 = 54    ✓
```

**验证（群 123456789，与 QQ 客户端逐人比对）**

| QQ | 客户端显示 | `64035` | 旧用 `64020` |
|---|---|---|---|
| 100000001（我/群主） | LV54 | **54 ✓** | 0 |
| 300000001 | LV62 | **62 ✓** | 7 |
| 300000004 | LV32 | **32 ✓** | 6 |
| 300000003 | LV10 | **10 ✓** | 0 |
| 300000005 | LV7 | **7 ✓** | 0 |
| 300000008 | LV4 | **4 ✓** | 0 |
| 300000009 | LV26 | **26 ✓** | 0 |
| 300000007 | LV26 | **26 ✓** | 0 |
| 300000002 | LV32 | **32 ✓** | 8 |
| 300000006 | LV25 | **25 ✓** | 0 |

**命中 10/10。**

→ 旧实现（v1.0~v1.2）用 `64020` 当等级，**错误**：
该字段值域仅 0~11，且与客户端显示的 LV 无对应关系
（群主/管理员常为 0，普通成员多为 5~11）。
**现改名为「活跃分级」(`active`)，不再作为等级输出。**

### 群角色字段：`group_member3."64017"`（v1.2 起）

| 值 | 含义 |
|---|---|
| 1 | 群主 |
| 2 | 管理员 |
| 0 | 普通成员 |

**验证依据**
```
· 抽查 64 个群 → 每群「64017=1」有且仅有 1 人（与群主唯一性吻合）
· 群 123456789 → 群主 1 人（100000001）+ 管理员 10 人，与 QQ 客户端一致
```

### ✗ 已废弃：`64027`（v1.0 / v1.1 的误用）

旧实现用 `64027 == 1` 判「管理员」，**错误**。实测反例：

```
群 123456789   2887 人 → 64027=1 的 369 人（13%）
群 123456799   3202 人 → 64027=1 的  95 人（ 3%）
群 123456798  2617 人 → 64027=1 的 270 人（10%）
```

管理员不可能占 3%~13%。该字段与角色无关
（群主、管理员、普通成员都可能取值为 1）。

### 成员数口径

```
group_list."60006"          = 服务端声明的成员数（准确）
count(group_member3)        = 本地缓存条数（可能含已退群残留 → 偏多）

实测（群 123456789）：服务端 1996 人 / 本地缓存 2887 人（+891）
→ 需要"群人数"时，以 60006 为准
```

### 群主校验用的原始字段

```
group_list."60221"   曾疑为群主 QQ，实测不成立
                     （抽查 20 个群，其值 0/20 能在成员表中找到）
```

## 十、QQ 频道

> 数据来源：`gpro_v1-*_<uid>.db`（ORM 系加密，口令纯离线可推）。
> 判据：`t_GPro_MemberRoleListInfo_v1_<guildid>` 表存在 **且** 该 id 在 `t_GPro_Guild_v15` 里。
> 原理详见 [频道库解密原理.md](频道库解密原理.md)。

### `guild-list [--all]`

我加入的频道。输出 `频道ID \t 名称`。`--all` 追加列出"仅浏览过、未加入"的。

```sh
su -c "zql guild-list"          # 42 行
su -c "zql guild-list --json"   # {joined:[...], visited:[...]}
```

### `guild-info <ID|短名|名称>`

频道详情：名称 / 短名 / 是否已加入 / 子频道数 / 身份组数 / 成员规模 / 我的身份组。

```sh
su -c "zql guild-info sample-channel"
```

### `guild-channels <ID|短名|名称>`

子频道列表，按分组输出，含类型与 ID。

```
[讨论组]
  200000002	使用交流 | 闲聊杂谈💤	文字
  ...
[帖子广场]
  200000001	📢入群必看	帖子
```

### `guild-roles <ID|短名|名称>`

身份组列表：`ID \t 名称 \t [标签] \t [颜色] \t N人`。
等级身份组显示为 `LV.n`（取自 `description_`）。

### `in-guild <ID|短名|名称>`

是否已加入 → `true` / `false`，退出码 0 / 1。支持三种定位方式（ID / 短名 / 名称）。
注意：仅"浏览过"的频道同样返回 `false`。

### `guild-msgs <频道ID> [--kw 词] [--n N]`（实验性，需 --exp）

频道消息检索，范围强制限定在本人已加入的频道。

```sh
su -c "zql guild-msgs 1000000000000001 --exp --n 6"
```

注意：短板：`guild_msg.db` 的部分页仅存在于 `-wal`，而 SQLCipher 的 WAL 帧加密方式与主库页不同
（尚未解出），**结果可能取不全**。故默认关闭，需显式 `--exp`，且输出带警示。
